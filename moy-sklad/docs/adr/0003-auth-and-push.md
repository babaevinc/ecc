# ADR 0003 — Вход и уведомления

- Статус: принято
- Дата: 2026-11-01

## Вход

- **Supabase Auth, email + пароль.** Сотрудников без email владелец заводит по телефону (Supabase Auth поддерживает телефон + пароль; SMS-провайдер подключается отдельно и стоит денег — решить при настройке).
- **Регистрация:** компанию создаёт владелец (или супер-админ). Сотрудников владелец приглашает из настроек — открытой регистрации в чужую компанию нет.
- **Пароль:** не короче 10 символов; хранит Supabase (bcrypt). Сессия — короткий access token и refresh token в `expo-secure-store`.
- **Защита от подбора:** лимиты попыток Supabase Auth + одинаковое сообщение для неверного логина и пароля (проверяется тестами `abuse`).
- **Удаление аккаунта** — из настроек приложения (требование App Store), через Edge Function `delete-account`.

## Уведомления

| Событие | Кому | Как |
|---|---|---|
| Новая заявка | `owner` и `staff` складов заявки, кроме автора | Триггер на `requests` → Edge Function `notify` → Expo Push |
| Заявка отгружена или отменена | Автор заявки и `owner`, кроме исполнителя | Тот же путь |
| Партия старше 7 дней | `owner` и `staff` склада, раз в день в 8:00 по Екатеринбургу | pg_cron → `notify` |

Каждое уведомление дублируется в таблицу `notifications` — лента в приложении работает и без push.

## Последствия

- Нужны аккаунты Apple Developer (APNs) и Firebase (FCM) для сборки с push — это шаг `dev-devops` перед первой публикацией.
- Тексты уведомлений не содержат цен и долгов: экран блокировки видят посторонние.
