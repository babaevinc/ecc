# ADR 0001 — Стек: Expo (React Native) + Supabase

- Статус: принято
- Дата: 2026-11-01

## Контекст

Нужно одно приложение для iPhone и Android, публикация в App Store и Google Play, вход по паролю,
роли, push-уведомления. Команда — ИИ-агенты и один владелец без собственного Mac.

## Решение

- **Приложение:** Expo SDK + React Native + TypeScript, навигация Expo Router, сборка и публикация через EAS Build/Submit (облачная сборка, Mac не нужен).
- **Сервер:** Supabase — PostgreSQL с RLS, Supabase Auth, Edge Functions, pg_cron.
- **Уведомления:** Expo Notifications (один API для APNs и FCM).

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Flutter | Хорошо, но веб-прототип и тесты уже на JS/TS; две технологии в команде — дороже |
| Нативные Swift + Kotlin | Два кода, нужен Mac для iOS |
| Свой сервер Node + PostgreSQL | Аутентификацию, RLS и cron пришлось бы писать и защищать самим |
| Firebase | Данные за рубежом без варианта самостоятельного размещения (см. ADR 0002); слабее модель прав для ролей и компаний |

## Последствия

- Права в двух местах: RLS в базе (главная защита) и проверки в RPC-функциях; приложение только скрывает недоступное.
- Supabase можно разместить самостоятельно — это оставляет выбор места хранения данных (ADR 0002).
